# Автоматическая проверка прототипа

Запускается сама после каждого коммита в `gh-pages`. Результаты — в ветке `qa-results`:
https://raw.githubusercontent.com/jonysilvervi/digital-store-docs/qa-results/latest/report.md

## Как устроено

1. **Подтверждение версии** (`wait-live.mjs`). Ждём, пока API GitHub Pages сообщит, что сборка этого коммита завершена, и HTML на сайте побайтно совпадёт с файлом коммита. Если в `gh-pages` уже есть более новый коммит — запуск ничего не публикует. Если версия не подтвердилась за 10 минут — отчёт «ПРОВЕРКА НЕ ВЫПОЛНЕНА».
2. **Проверки** (`run.mjs`, `checks.mjs`) на опубликованном сайте, адрес с параметром версии `?v=<коммит>`:
   - логика: каждый способ доступа × каждый его срок — цена «от» с фактическим сроком, приватность, условия, цены и месячный эквивалент сроков, наличие, итог, кнопки, количество до предела и обратно, объяснение предела (наличие или лимит заказа), «Понадобится», корзина;
   - автоматические изменения выбора (реестр А7): смена тарифа — новый выбор с пояснением; внутри тарифа — смена и восстановление срока и количества с пояснением; пояснение видно на экране сразу после нажатия;
   - листы, вопросы, служебный режим;
   - правила отображения на 320, 390, 480, 600, 768, 900, 1280 и 1440 px: прокрутка, обрезка, перекрытия, закреплённая панель, текст не мельче 13 px, контраст текста не ниже 4,5:1, сенсорные цели не меньше 44 px;
   - регрессионные тесты `regress.mjs` (реестр В-07, см. `REGRESSION_TESTS.md`) — отдельным процессом, результат входит в общий отчёт.
3. **Ожидаемые значения** считает `oracle.mjs` из блока данных `#catalog` файла коммита — независимо от кода страницы.
4. **Снимки** (`visual.mjs`) по типам состояний, сравнение с предыдущими снимками и эталоном, сводные листы (до 6 экранов), снимки ошибок с красной рамкой.
5. **Публикация** (`publish.sh`) в `qa-results`.

## Режимы

- **Логика и правила отображения — всегда полностью.**
- **Снимки:** быстрый режим — 5 экранов; полный — около 36.
- Полный режим выбирается сам, если изменились стили страницы, сама система проверки, или нет предыдущих снимков.
- Пометки в описании коммита `gh-pages`: `[qa:full]` — полный режим; `[qa:fast]` — быстрый; `[qa:baseline]` — полный режим и, если всё пройдено, снимки становятся эталоном.
- Повторить проверку вручную: Actions → нужный запуск → «Re-run all jobs».

## Новые товары и предложения

- Новое предложение, срок, тариф или состояние наличия добавляется только в блок данных `<script type="application/json" id="catalog">` — проверки и снимки подхватят его сами.
- Новая **страница** магазина (каталог, корзина и т. п.) потребует своего набора проверок: правила отображения переиспользуются, логику страницы нужно описать.

## Три режима запуска

1. **Короткая проверка затронутого** (минуты): регрессионные тесты по номерам и нужные группы сессий на одном экране.
   `ONLY=R-24,R-27 BASE_URL=… node regress.mjs` · `SCEN=Ж VIEWPORTS=390x740 BASE_URL=… node sessions.mjs`
2. **Покупательские сессии** (группы А–И, `SESSIONS.md`): `BASE_URL=… node sessions.mjs`, по умолчанию 320×568 и 390×740.
3. **Итоговая общая проверка** — один раз после завершения изменений: `LOCAL_RUN=1 QA_MODE=full BASE_URL=… node run.mjs`. Она включает логику, переходы, листы, отображение на 8 ширинах, регрессионные тесты и сессии на 320×568, 390×740, 819×900, 820×900, 1280×800. Тот же прогон идёт в GitHub Actions после публикации.

## Локальный запуск

```
cd qa && npm ci
LOCAL_RUN=1 BASE_URL=http://127.0.0.1:8099/index.html node run.mjs
```
(сайт раздаётся локально, например `python3 -m http.server 8099` из корня ветки).
