# Покупательские сессии

`qa/sessions.mjs` — последовательности действий покупателя с накопленным состоянием.

## Как устроено

- **Начало.** Каждая сессия начинается с обычной страницы, без `?demo`.
- **Действия.** Внутри сессии страница не перезагружается. Состояние не подставляется ни адресом, ни служебными функциями. Все действия идут через интерфейс: нажатия, клавиатура, прокрутка, листы справки, «В корзину», «Уведомить».
- **Ожидания** считает `session-model.mjs` — независимая модель. Она знает только данные каталога и правила реестра: А3 (цены), А4-07 (ограничения количества), А7 (переходы, память выбора, ближайший срок), Г-04 (единственный способ выбирается сам), А12-02 (добавление в корзину — имитация). Состояние страницы модель не читает.
- **После каждого шага** сравнивается:
  - выбранные тариф, способ, срок, количество; состояние «+» и «−»; объяснение предела (наличие или лимит заказа, единицы способа);
  - статус у каждого недоступного срока;
  - итог: строка выбора, сумма, состав «N единиц × цена», месячный эквивалент заказа;
  - кнопки, доступные в этом состоянии;
  - пояснение: ровно то, что изменилось не по прямому действию. Сразу после такого действия пояснение видно на экране;
  - счётчик корзины — сумма добавленных количеств; сообщение о добавлении содержит текущую, а не промежуточную конфигурацию;
  - главное действие видно и нажимается. Поверх открытого окна оно не нажимается — ни по `inert`, ни визуально;
  - после выбора способа его сроки на экране, без поисковой прокрутки;
  - нажатый элемент остаётся под пальцем (допуск 30 px; после выбора способа — остаётся на экране);
  - фокус остаётся на нажатом элементе, а при работе с клавиатуры не уходит под панель;
  - ошибок JavaScript нет.
- **При ошибке** сессия останавливается. В `failures/<сессия>--<экран>.json` записываются:
  - сценарий, версия, размер экрана, набор данных, seed;
  - последовательность действий, ожидаемое и фактическое состояние;
  - список расхождений и команда повтора (`repro`).

  Рядом лежит снимок проблемного шага.

## Группы сценариев

| Группа | Что проверяет | Сценарии |
|---|---|---|
| А | Несколько единиц одного варианта: увеличить, уменьшить, предел, попытка превысить, добавить | A1 лимит заказа, A2 предел по наличию, A3 остаток 1 при лимите 3 и 21 место из 25 (синтетика) |
| Б | Один тариф, разные способы и сроки, несколько разных позиций | Б1 |
| В | Повторное добавление одного варианта с разным количеством | В1 |
| Г | Несколько тарифов за сессию, сброс по А7, сохранность добавленного | Г1 |
| Д | Передумавший покупатель: меняет всё, открывает три справки, добавляет | Д1 |
| Е | Ограничения и недоступность, «Уведомить» не меняет корзину | Е1, Е2, Е3 (синтетика: по одной штуке, ожидается, нет в наличии) |
| Ж | Память выбора: А → Б → А, А → Б → В → А, ближайший срок, равное расстояние | Ж1 (синтетика), Ж2, Ж3 |
| З | Длинная сессия | З1 фиксированная; З#seed — смешанные воспроизводимые |
| И | Двойные и быстрые нажатия; только клавиатура | И1, И2 |

**Наборы данных** (`DATA`):
- `demo` — каталог страницы;
- `memory` — сроки 2/12, 1/3, 3/6 и способ по одной штуке;
- `limits` — остаток 1 при лимите 3, лимит 25 при остатке 4, «ожидается», «нет в наличии».

Варианты для сценариев подбираются по данным, а не жёстко заданным сочетанием.

## Запуск

Из папки репозитория, страница раздаётся локально (`python3 -m http.server 8099`):

```
# короткая проверка затронутых сценариев: одна группа, один экран
SCEN=Ж VIEWPORTS=390x740 BASE_URL=http://127.0.0.1:8099/index.html node qa/sessions.mjs

# одна сессия по команде из failures/*.json
SCEN=Е1 VIEWPORTS=320x568 DATA=demo BASE_URL=… node qa/sessions.mjs

# все покупательские сессии: два мобильных размера, 2 смешанные сессии по 30 шагов
BASE_URL=… node qa/sessions.mjs

# граница 819/820 и компьютер
VIEWPORTS=819x900,820x900,1280x800 BASE_URL=… node qa/sessions.mjs

# воспроизвести смешанную сессию
SCEN=З MIXED=1 SEED=7 STEPS=30 BASE_URL=… node qa/sessions.mjs

# снимок каждого шага для просмотра глазами
SHOTS=1 SCEN=Д1 VIEWPORTS=320x568 BASE_URL=… node qa/sessions.mjs

# итоговая общая проверка: логика, переходы, отображение, регрессия и сессии на 5 размерах
LOCAL_RUN=1 QA_MODE=full BASE_URL=… node qa/run.mjs
```

Настройки:
- `SCEN` — сценарии или группы через запятую;
- `VIEWPORTS` — размеры экрана;
- `DATA` — набор данных для смешанных сессий;
- `MIXED` и `STEPS` — число смешанных сессий и шагов в каждой;
- `SEED` — начальное значение генератора;
- `SHOTS` — снимок каждого шага;
- `OUT_DIR`, `LABEL` — куда писать отчёт и какую версию в нём указать.

В общем прогоне размеры сессий задаёт `SESSION_VIEWPORTS`.

## Проверка самих сессий

В страницу по одной вносились 7 поломок. Каждую поймали сессии на 390×740:
- нет доведения до сроков;
- устаревшее пояснение не убирается;
- прежний шаблон итога;
- кнопка покупки поверх окна;
- двойное добавление;
- потеря фокуса;
- самый короткий срок вместо ближайшего.

## Границы

- **Корзины и оформления в прототипе нет** (А12-02). Проверяются выбор, сообщение о добавлении с текущей конфигурацией и счётчик. Состав корзины, объединение и разделение позиций, удаление, изменение количества в корзине, итог заказа, оформление и оплату проверить нельзя: этих функций нет. Скрытая «правильная корзина» внутри теста не строится. Модель только записывает, что было добавлено, чтобы сверить счётчик и сообщение.
- **«Уведомить»** — демо-форма. Проверяется только то, что она не создаёт покупку и не меняет корзину.
- **Двойное нажатие «В корзину»** сейчас добавляет дважды: правила защиты нет. Это вопрос владельцу. Сессия И1 фиксирует текущее поведение как ожидаемое, чтобы ловить случайные потери и лишние дубли.
- **Браузер.** Проверка идёт в Chromium с имитацией размера экрана. Это не настоящий телефон: Safari и Firefox, жесты, экранная клавиатура, системный размер шрифта, вырезы экрана и программы чтения с экрана не проверяются.
- **Шрифт.** Локально Golos Text не загружается (сеть ограничена), используется запасной шрифт. В GitHub Actions — настоящий.
