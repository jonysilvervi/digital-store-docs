# Регрессионные тесты

Рабочая ветка `work/regressions`. В `gh-pages` эти файлы попадут вместе с исправлением макета. Тесты запускаются и в общей автопроверке (`run.mjs`).

**Правило (реестр В-07):** каждый тест сначала падает на версии с ошибкой, затем проходит после исправления. Сам тест при этом не меняется — это видно в истории коммитов этой ветки.

## Как устроены

- Ожидания берутся из данных каталога и требований реестра, а не из кода страницы.
- Тексты дословно не закреплены. Срок проверяется по формам из словаря («N мес.» или «N месяц/месяца/месяцев»), предупреждение о приватности — по смыслу.
- Синтетические каталоги подставляются в загружаемую страницу при проверке; сама страница не меняется.
- Селекторы (`#offers`, `.offer`, `#terms`, `#qtySec`, `#bar`) — крючки текущего серого макета (уровень С). При утверждённом дизайне меняются вместе с требованиями уровня С.

## Изменения тестов при переработке конструкции 22.10

Смысл тестов не менялся. Обновлены только крючки серого макета (уровень С), которые закрепляли прежнюю разметку:
- **R-10a, G-05** — заголовок «Количество» теперь `h3`, а не `h2`. Тест исключает его из текста у счётчика.
- **R-33** — состав и месячный эквивалент стали одной строкой итога вместо двух. Тест по-прежнему требует, чтобы каждая строка итога не разрывалась.

В общей проверке (`checks.mjs`):
- **Строка выбора** проверяется в `#ctx`, а не во фразе «за N мес.» внутри суммы.
- **Состав итога** — «N единиц × цена».
- **Статус у каждого недоступного срока.** Прежнее правило «без повтора статуса» заменено по поручению владельца 22.10 (см. журнал реестра).
- **Лист сравнения** — карточки `.tcard`.
- **Вопросы** открываются из компактного входа.
